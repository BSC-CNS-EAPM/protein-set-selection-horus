Installation#

This page takes you from nothing to a working plugin in six steps:

  1. install Horus;

  2. install the plugin;

  3. install the external tools;

  4. point the plugin at the tools;

  5. set up your cluster, if you use one;

  6. check it with the example data.

Requirements#

  • A Linux or macOS machine for the Horus desktop app. There is no Windows build; on Windows, use the Horus web app (see Step 1).

  • External tools for the heavier stages: MMseqs2, MAFFT, PyTorch (for ProteinMPNN), Rosetta and PyRosetta, BioEmu, CodonTransformer and, optionally, SMOG2. Which ones you need depends on the blocks you use and where they run; see Tools and configuration. Step 3 installs them.

  • micromamba, mamba or conda, to create the environments the tools live in.

  • Disk space: several GB for the tool environments (PyTorch, BioEmu and PyRosetta are the large ones), plus about 75 GB while Rosetta installs if you install it locally.

  • A SLURM cluster is recommended for anything beyond a small test: ProteinMPNN and BioEmu want a GPU, and a Rosetta relax of many models is a cluster job. Any SLURM cluster works: you name its queue, modules and environments in the block settings. See Remotes and clusters.

Important

Rosetta and PyRosetta need a licence. They are free for academic and non-commercial use under the Rosetta Software Non-Commercial License Agreement, which covers the Rosetta Relax and Analyse Rosetta Relax blocks. Commercial use, including fee-for-service work done by an academic group, needs a commercial licence from the University of Washington (license@uw.edu). Neither download asks for a login, so it is up to you to check that your use is covered. See Rosetta licensing.

Step 1: install Horus#

Download the latest Horus release for your system from the Horus releases page.

Linux

  1. Download the .deb (Debian, Ubuntu) or .rpm (Fedora, Rocky, RHEL) package.

  2. Install it with your package manager:

    sudo apt install ./horus_<version>.deb      # Debian, Ubuntu
sudo dnf install ./horus-<version>.rpm      # Fedora, Rocky, RHEL

  3. Start Horus from the application menu, or from a terminal with horus.

macOS

  1. Download the .dmg.

  2. Open it and drag Horus into your Applications folder.

  3. Start Horus from Applications.

Windows

There is no Windows build. Use the web app at horus.bsc.es, or run Horus on a Linux machine or server and open it from your browser.

From source

To run Horus from its repository instead (for developing Horus or plugins), follow the README in the Horus repository: it installs micromamba and Bun (or Node.js 18), creates a horus environment with bun run requirements, and starts the app with python Horus.py --debug --server.

Where Horus keeps its data

Horus stores its plugins, configurations and settings in its AppSupport folder. You need it in Step 4 if you save the tool paths from a terminal.

Horus installed as

AppSupport folder

Linux package

~/.local/share/com.bsc.horus

macOS app

~/Library/Application Support/com.bsc.horus

From source

AppSupport/ in the Horus checkout

The HORUS_APP_SUPPORT_DIR environment variable overrides it. Horus prints the folder it uses in its log at start-up (AppSupport Dir: …).

Step 2: install the plugin#

  1. Download protselect-<version>.hp from the plugin's releases.

  2. In Horus, open the Plugin Manager and use Install plugin to select the .hp file.

  3. Horus installs the plugin and its Python dependencies (listed in plugin.meta) into the plugin's own deps/ folder. Follow the progress in the Installation logs, and wait for it to finish.

  4. The Protein Set Selection blocks appear in the block palette, and the plugin adds an Environment Setup page.

Install the plugin from the Plugin Manager rather than by copying it into the plugins folder. The desktop app refuses to install dependencies while it starts, so a copied plugin loads without them. If that happens, reinstall from the Plugin Manager, or start Horus with --server once so the dependencies install at start-up.

Python dependencies#

Installed automatically with the plugin:

  • numpy (below 2.5), pandas, scipy, pyyaml, matplotlib, seaborn, tqdm, biopython 1.81, mdtraj, ipywidgets;

  • bsc_calculations: writes and submits the cluster job scripts;

  • prepare_proteins: Rosetta, BioEmu and structure handling;

  • bioprospecting-horus: a trimmed bioprospecting with the ProteinMPNN, MAFFT and CodonTransformer code the blocks use, including the ProteinMPNN weights.

PyTorch is not installed with the plugin; Step 3 installs it.

Step 3: install the external tools#

Each external tool is installed in its own environment. There are two ways to install them; both install the tools in the same places, so you can mix them.

From Horus: the Environment Setup page. Open the page the plugin adds. For every tool it shows whether it is found, where, and which blocks need it, with an Install button for MMseqs2, MAFFT, PyTorch, PyRosetta, BioEmu and CodonTransformer. It only detects Rosetta and SMOG2.

From a terminal: install_deps.sh. The installer at the root of the repository checks every tool, says which blocks need it and asks before installing it. It also installs Rosetta and SMOG2, and works before Horus is installed.

git clone https://github.com/BSC-CNS-EAPM/protein-set-selection-horus.git
cd protein-set-selection-horus
./install_deps.sh --check     # see what is already there
./install_deps.sh             # install what is missing, asking first

If you have no micromamba, mamba or conda, install micromamba first and open a new shell:

"${SHELL}" <(curl -L micro.mamba.pm/install.sh)

All of the installer's options, what it installs where, and how to install Rosetta offline are in The dependency installer.

Tip

Install only what you will run locally. A block that runs on a cluster remote uses the cluster's modules and environments, not these. If ProteinMPNN, BioEmu and Rosetta all run on the cluster, locally you only need PyRosetta, CodonTransformer, MAFFT and, for local clustering, MMseqs2.

Step 4: point the plugin at the tools#

The blocks find the local tools through the plugin's configurations, which Horus stores per remote. Fill them in one of three ways:

  • on the Environment Setup page, press Save detected paths, then reopen the configurations in Horus to see the new values;

  • run the installer with --config, pointing at the Local remote's configuration file in the AppSupport folder from Step 1:

    ./install_deps.sh --config ~/.local/share/com.bsc.horus/config/protselect/protselect_Local.json

    Run it while Horus is closed, or restart Horus afterwards, so Horus reads the new values;

  • enter the values the installer prints at the end by hand, in the plugin's configurations with the Local remote selected.

Rosetta, BioEmu and SMOG2 are not read from the configurations yet. Set them on the blocks instead: the Rosetta Relax block's Rosetta executable (and Rosetta path for symmetry), the BioEmu Sampling block's BioEmu environment, and smog2 on the PATH Horus runs with. The installer prints these values too. See Tools and configuration.

Step 5: set up your cluster (optional)#

To run the heavy blocks on a SLURM cluster, add the cluster as a remote in Horus's Remotes manager (a CPU remote and, on clusters with separate GPU login nodes, a GPU one), then check each block's cluster software settings against your site. Remotes and clusters explains which block goes where and how to size the jobs.

Step 6: check the installation#

  1. Run ./install_deps.sh --check. It ends with a summary; every tool you need should read ok or installed. It exits with status 1 while a required tool is missing.

  2. In Horus, open the Environment Setup page and check the same.

  3. Open the ProteSel Pipeline preset from the plugin's presets. Its input blocks come filled in with the small lysozyme example. Lower the expensive settings (Rosetta nstruct 2 with CPUs 3, BioEmu num_samples 10) and run it. See The workflow and Example data.

If a block cannot find a tool, see Troubleshooting.

Developing the plugin#

To work on the plugin itself, clone the repository and link its ProtSelect folder into Horus's plugins folder:

git clone https://github.com/BSC-CNS-EAPM/protein-set-selection-horus.git
ln -s "$PWD/protein-set-selection-horus/ProtSelect" <horus>/AppSupport/Plugins/ProtSelect

Restart Horus after changing a block's code. A block already placed in a flow keeps a snapshot of its parameters, so a block that gained a new parameter must be removed and added again to show it.

Building these docs:

micromamba create -f Devtools/Environment/docs.yaml
micromamba activate protselect_docs
cd docs && make html
